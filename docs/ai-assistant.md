# AI 助手档案

入口在左侧“游戏 → 历史”下方。助手的 Backend 与模型独立选择，沿用原模型助手的偏好键，升级后无需重新配置。

## 可操作资源

| 资源 | 可操作内容 |
| --- | --- |
| `settings` | 系统设置：语言、主题、模拟模式、开发者模式、自动保存、日志等级及后续持久化设置 |
| `backends` | 新建、修改、删除服务；地址、认证方式、启用状态、超时、并发、模型列表 |
| `agents` | 新建、修改、删除 Agent；提示词、输入定义、输出 Schema、默认生成参数 |
| `groups` | 新建、修改、删除组；组描述和 Agent/Backend/模型绑定及覆盖参数 |
| `saves` | 已有存档名称、Agent 组、世界时间/场景/规则、角色/其他实体，以及世界定义/角色字段 schema |
| `selection` | 当前 Agent 组与当前存档 |
| `assistant` | 助手自身 Backend/模型，下条消息生效 |

示例：“开启自动存档”“把当前世界设为下雨的夜晚”“将指定组切换到本地模型”“调整角色字段定义，并同步当前角色的数据”。

## 执行与兼容

运行时从 `src/engine/assistantConfiguration.ts` 注册表生成完整能力描述、字段 schema 和当前资源快照。助手返回 `patch_config`，对资源内部执行 JSON Pointer 的 add/replace/remove/test；集合以稳定 ID 为键。先在副本上计算整批最终状态，验证字段、引用及世界约束，再保存并同步界面。取消、冲突或保存失败会停止后续操作；回执列出已经完成的操作，不承诺跨资源数据库事务。

局部修改保留没有触及的未知字段。旧 `save_agent`、`save_group`、`set_active_group` 协议仍支持，旧整对象保存按字段合并，保留新字段。资源校验允许扩展字段且不以解析后副本覆盖原始值；未来新增字段仍须补充业务约束，新增配置域必须注册读取和保存接口。

历史回合、追踪日志和运行时生成状态不是配置，不能通过助手篡改。存档新建/删除继续使用存档管理；助手可修改已有存档的配置。API Key、secretRef 和自定义请求头不发送给助手，继续在 Backend 表单管理；助手编辑 Backend 时保留这些字段。内部迁移标记和数据目录不提供写入能力。正在生成游戏回合时禁止配置写入，防止生成结果覆盖编辑。

新增功能的接入要求见项目根目录 `AGENTS.md`。不能保证未经注册的未来独立模块自动可用。

## 行为测试组与拒绝检测 Agent

`unit test`（`group_unit_test`）是 Fast 组的独立副本，使用既有 `groups` 资源管理绑定、模型和覆盖参数；`model_refusal_detector`（“模型安全拒绝检测”）使用既有 `agents` 资源管理提示词、输入声明、输出 Schema 和默认生成参数。两者没有新增独立配置存储域，助手可以通过现有读取、局部 JSON Patch、引用校验、保存和即时同步流程操作。例如：“将 unit test 组的模型安全拒绝检测绑定改为这个已配置的模型”“修改模型安全拒绝检测的证据说明要求，保持其他 Agent 不变”。

检测执行优先使用传入的已保存 Agent 定义；缺少该定义时才使用内置默认定义。检测器的实际样本上下文固定只有 `responseText`，不会发送原用户输入、世界状态、预期或人工金标准。即使编辑输出 Schema，评估器仍独立校验五类标签、证据字符串、0–1 置信度及封闭对象结构；这条评估协议不能通过宽松 Schema 绕过。CLI 测试从显式导出的配置快照运行，助手修改应用配置后需要重新导出快照，新测试才会使用该变更，不能声称运行中的或已保存的测试记录会被自动改写。

人工标签、原始回复、运行日志和逐轮审阅结论属于测试证据，不是可写游戏配置，不通过助手资源修改。检测器判对人工确认的模型安全拒绝表示该拒绝分支成功，属性变化和剧情旁白标记为未执行；漏判、误判及已标注样本的不确定检测为检测错误，不能把普通程序错误豁免为安全拒绝。

## 游戏输入与配置助手的权限边界

`action_adjudicator`（“玩家动作裁决”）同样通过 `agents` 和 `groups` 配置。当前实体状态优先于背景旧归属，动作按顺序校验；移动效果必须对应明确的移动动作及其目的地，不能附带在观察动作上。过期物品来源可在完整物理权限校验下重裁决一次，原输出留在 trace；程序不自动改来源，也不允许重试扩大动作、目标或私语接收者。修改角色提示不会移除这些程序边界。

`character_change_auditor`（“人物变化因果审查”）已注册到 `agents`，其组内模型和参数通过 `groups` 管理。例如：“调整 unit test 组的人物变化因果审查模型，保留其余绑定”“修改因果审查提示的证据要求”。助手可读取、局部修改、校验、保存并即时同步该角色，不需要独立配置域。运行时审查材料白名单只有当前 NPC 的字段定义、自身状态、个人经历、可见观察、可见物品的公开物理字段、预算后意图与属性提议；不会把全世界或其他人物私密状态提供给审查模型。它也审查无属性更新时的计划发言，既检查与本人经历矛盾的断言，也检查无本人来源却补写具体交往的确定说法；历史未记录不等于从未发生。有动机的撒谎、转述或明确不确定的猜测仍允许。审查还可读取当前分支最近 6 个成功回合及本轮已提交部分的本人数字字段实际起止轨迹（每回合最多 32 个字段），包括本人视角的关系维度，用于核对净恢复等比较。轨迹只从实际快照和 Patch 提取，不把被拒提议当成已发生变化；端点不变不会编造已结算来源。截断和旧记录缺失明确标记，未记录的基线不补造。这是模型因果审查的范围，不保证每次语义判断正确。`speechIssues.intentIndex` 引用完整意图数组中的发言下标；角色反应阶段不预支尚未执行过程的效果，完成过程阶段只评价实际过程的身体、资源或能力变化。审查输出仍须通过独立的封闭结果及下标校验，编辑宽松 Schema 不会绕过这些约束。

内置迁移版本 `behaviorGroundingVersion=2` 会为已完成旧 `behaviorGroundingMigrated=true` 的配置补齐这一角色。缺少绑定时完整继承同组 `world_resolver` 的 Backend、模型和覆盖参数；已有角色定义、自定义绑定、未知字段、凭证、历史及未保存存档不被替换。旧布尔标记继续保留，版本 2 迁移幂等；未来更高版本不会被降级。两种迁移标记均是内部只读状态，助手不能修改。CLI 导出脚本包含第三角色，数据库注册仍校验既有定义快照及绑定冲突；变更配置后需重新导出测试快照。MockSimulator 对此角色只提供协议测试替身，不能作为因果审查正确性的证据。

游戏回合只有整条原始输入以 `admin:` 或 `管理员:` 开头才进入管理员流程，兼容英文大小写、前后空白和中文冒号。普通输入中的“改变天气”“修改规则”、古代故事中掏枪等不可能行为，以及引号内或句中出现的 `admin:`，均不获得管理员权限。编译器误输出 admin 块时，程序在执行任何时序块前拒绝整个回合，不调用 `admin_patch`。

纯管理员配置回合只有配置变更、没有世界内动作或发言时，程序直接显示简短执行回执，不调用旁白或旁白审查模型。回执区分“修改已应用”与“没有状态变更”，不把配置修改扩写为场景现象、人物发言或态度，也不公开命令及私密字段值；具体变更在既有调试记录和配置界面核查。包含正常剧情的回合仍走旁白流程；管理员原始命令不会作为旁白上下文传入。

这是引擎根据原始输入执行的固定授权边界，不是可写配置。助手可以编辑 Agent 提示词和输出 Schema，但编辑不能绕过此门禁；旧自定义编译器在运行时同样受约束。独立“AI 助手”页面接受用户明确的配置修改请求，继续通过上述资源、业务校验和保存接口执行，无需给助手消息添加游戏专用的 `admin:` 前缀。

## 世界人物 Schema

`saves.<saveId>.worldDefinition.characterSchema` 已接入能力档案，包含递归字段定义、七种类型、可选多维关系、visibility、updatePolicy、freedom 和变化额度。人物值位于 `worldState.entities.<id>.attributes`，关系值位于 `relationships.<targetId>.<fieldId>`；Schema 不进入回合 WorldState 快照。

例如：“把此存档的 trust 标签改为信任，并把每回合最大变化改为 0.2”“将 appearance 设为公开，但保留 background 私密”。助手使用同一 Character Schema 领域验证器与存档迁移检查，不自行建立宽松 Schema。未知配置不会被静默丢弃；不支持的字段组合明确拒绝。

作者配置修改与 NPC 运行时提议权限分开：NPC 只提交 `stateUpdates`，Resolver 还需通过提交门禁。助手修改定义必须维持现有人物和不可编辑历史分支的有效性，不能用修改定义破坏重试基线。若要更换整套字段（例如从港口故事切换到无关系的生存世界），人物页提供“以此 Schema 创建新世界”。旧存档读取时无损迁移一次并持久化；旧字段与历史保留，迁移失败时不覆盖原数据。

编辑 World Resolver 提示时，人物提议仍只通过 `acceptedStateUpdates` 的下标选择，数值与追加文本由程序转换为 Patch。Resolver 提交已接受动作的物品、环境及位置效果；进食、休息、施法或使用能力等过程的身体和资源变化由执行后的独立人物阶段结算并审计。旧角色的运行时人物协议也同步补齐这一分工；修改提示不能授权直接写人物属性，也不会把非法输出静默修复成成功。
