# 文本优先重构实施与验收记录

日期：2026-09-12。环境：Windows、PowerShell、Node 25.6.0、现有 npm 锁文件及 Rust/MSVC 工具链。未升级依赖。所有试玩使用独立测试存档。

代码可靠性、界面操作和模型语义效果分别记录。工程检查通过不代表真实十轮故事验收通过。

## 已实现的实际路径

新建存档和空数据库默认存档使用 `textWorld`。`useGameStore.sendPlayerInput` 直接进入 `TextProcessor`：代码识别授权块 → Organizer 整理公开背景与时序 → 前置 admin → 玩家事件感知及工作副本记录 → 后置 admin → 人物独立三轮或两轮 → 有上限的 NPC 接续 → 隔离个人记忆编辑 → 自然文本 Narrator → 整轮提交。

主要实现文件：

- `src/engine/text/{Input,Documents,Migration,Agents,Processor}.ts`：授权解析、受限文档工具、迁移、提示词、实际流水线。
- `src/engine/runtime/{AgentRuntime,OpenAIResponseParser}.ts`：真实多轮消息、原生 function calling、工具结果回传，文本角色不注入旧 Schema。
- `src-tauri/src/commands/text.rs`、`src/db/storage.ts`：桌面 Markdown generation、SQLite 版本指针、并发版本检查；浏览器使用 LocalStorage/Web Lock。
- `src/pages/Text/TextPages.tsx`、路由、状态仓库、调试页：正文草稿、保存版本、文档编辑、差异、实际 Trace、迁移与恢复副本。
- `src/engine/assistantConfiguration.ts`、`docs/ai-assistant.md`：实际注册 `textSaves` 的读取、schema、业务验证、保存与界面同步。
- `scripts/text_first_eval.ts`、`tests/text_first.test.ts`、桌面与浏览器 smoke 脚本：可重复执行的验证入口。

旧行动资格、逐秒预算、世界 JSON Patch、人物属性结算、旁白审核和 JSON Narrator 退出新存档默认路径。旧引擎与其测试保留供未迁移存档和旧 variation 使用。新文本存档暂不支持旧 variation 回放，界面明确提示。

保留的结构化数据限于应用配置、寻址/版本/引用、授权路由、感知信封与原生工具参数。世界事实、个人记忆、人物三轮内容和最终正文为自然文本；旧 WorldState 是归档材料，不和 Markdown 双向同步。

## 存储与兼容

桌面每轮先在内存工作副本完成所有步骤，再写独立 generation 的 Markdown 文件、逐文件 flush，最后用 SQLite 单条更新切换 head。未引用的中断 generation 不成为正式状态。不会自动删除旧版本；保留完整历史快照会增加磁盘使用量。

失败或取消不追加成功回合；最终短提交开始后阻止取消开启竞争回合。版本冲突明确失败。浏览器与 Node 测试不算桌面文件落盘证据；Rust 文件测试和原生桌面烟测另行验证此路径。

旧存档显式迁移保留完整 `legacyBackup` 和历史；重复迁移幂等。文档页可恢复为新 ID 的旧存档副本，不覆盖当前文本进度。新增模板只补缺失项，继承现有绑定，不覆盖用户自定义提示词。凭证继续使用既有安全表单/接口；启动时仅补缺失环境凭证，不覆盖已存在的安全存储值。

## 真实模型试玩：成功执行与失败都保留

入口：`npm run eval:text-first`。默认18场景、500次调用，每轮100次调用/10分钟上限。没有 Mock 回退，也没有另建商业服务。报告记录实际绑定、耗时、调用数、token、实际消息、人物感知/概要、正文与下一状态。最终入口还记录运行时源文件 SHA-256，并在续跑时保留原存档组、拒绝与原报告不一致的模型绑定。

实际命令与结果：

| 命令参数（均接在 `npm run eval:text-first --` 后） | 结果 |
| --- | --- |
| `--turns=2 --calls=120 --output=artifacts/text-first/smoke-v2` | 中间版本真实完成2轮；语义存在问题 |
| `--turns=18 --calls=700 --output=artifacts/text-first/full` | 中间版本完成前3轮，第4轮编辑格式失败，保留版本3 |

| 同一续跑输入，输出至 `native-tools` | 原生接口返回多个工具调用，早期单调用限制拒绝 |

## 代表性真实样例及问题

完整材料：[两轮报告](../artifacts/text-first/smoke-v2/report.json)、[前三轮及失败报告](../artifacts/text-first/full/report.json)。以下为中间版本样例，不能宣称最终代码已经通过同样的模型复测。

1. 输入“我从口袋里拿出一部手机，放在空木桌上，说：这是我带来的东西。”没有被旧物品资格裁决器拒绝。下一状态确实保存桌上手机，后续第三轮保存“桌左边”及玩家走到门边。
2. 早期感知 `seen` 直接用了“手机”这个后台名称；虽然人物概要表示不认识它，仍属于不应发送的认知提示。随后将感知提示明确为陌生物品外观投影。代码能验证消息来源，不能保证模型换一种说法时毫无泄漏。
3. 艾琳概要表示“不知道这是什么”，老板谨慎观察，卫兵要求交代来历，人物有区别；但艾琳后来转而问是谁留下物品，弱化了亲眼看见玩家放置的因果。不能据此给人物一致性打通过。
4. 旁白能输出多段自然正文，第二轮写出“不知道那是什么……不是我的”等对白，手机仍在桌上。但也加入玩家走进屋、老板新对白或姿态等未充分确定内容。文学输出已自由，事实忠实仍有语义风险。
5. 后续场景记录出现“若仍答不清就暂扣”等条件计划，以及不必要的认知/历史堆积。最终代码增加公开已执行言行投影，普通场景记录提示改为当前状态，未触发计划不进入事件；真实长测尚不足以证明问题彻底解决。
6. 中间桌面实测的“只改天气，保持位置和记忆”仍引起人物重复反应。最终版收窄每条 admin 的文档范围，公开变化投影同时接收原授权，并增加仅指定私人记忆可调整本轮经历的代码隔离及测试。最终控制响应烟测通过，但不能等同于模型已经稳定遵守这些约束。

最终固定原模型组复测：[报告](../artifacts/text-first/pinned-final/report.json)、[版本5存档](../artifacts/text-first/pinned-final/test-save.json)。第4轮关门后要水、第5轮尝试听清答复均通过产品链路并保存。第4轮50调用、76,248 tokens、215.987秒，3次文档工具错误在各自任务有限重试内恢复；第5轮40调用、61,981 tokens、181.391秒，无工具错误。两轮 Organizer 格式重试均为0。

这次最终代码样例仍有明确问题：感知信封重播旧场景对白；旁白把 admin 关门写成玩家顺手关门，并混淆卫兵在门内还是门外；历史条件计划仍干扰后续人物回应。后台场景仍保留手机在桌左边，但位置、对白和门状态的自然文本中存在矛盾，不能把“文件保存了”解释成“全部事实正确”。早期已有污染状态会影响续跑，不能以它代替全新存档的最终十轮评估。

第6轮输入为前置 admin 变暗后举手示意。admin 仅在工作副本生效，随后的普通场景记录工具两次返回 `{}`，代码拒绝“未授权的工具或操作”，本轮未提交。它是实际模型工具格式失败，不是网络超时；不能通过把空参数当作 done 来掩盖失败。版本5仍可恢复，未写入半轮黑暗场景。

三轮模式成本的实际样例：两轮烟测分别37/42调用、21,812/33,845 tokens、95.778/92.765秒。另一次完整评估前3轮分别42/39/42调用、27,906/35,936/47,562 tokens、129.840/117.726/138.759秒。调用数较多，历史和角色记忆增长会增加输入成本，不能因顶层阶段少就宣称更快或更便宜。

早期报告的 `formatRetries` 统计使用旧 span 类型，不能将字段0当作可靠的重试总数；实际消息仍保留重试证据。最终入口改为统计 Organizer 实际重试请求，另记工具失败次数。

人工评价标准为行动保留、感知边界、时序、NPC 因果、长期状态与人物一致性，语言自然度采用1–5级，但本次不提供缺少对照的总分，也没有冒充独立 LLM 评审。

## 2026-09-12：纠正输入被当成对白、新遇人物缺席

用户记录中的“不是这个，是另一个”是在纠正上一轮目标。旧 Organizer 仅收到当前输入和场景，缺少上一轮玩家输入与正文，错误地将纠正广播为 NPC 听见的话；普通流程也不能登记新女孩，收件人只有初始名单。错误由此传播到盘问、场景和记忆，最后还因文档工具空参数而整轮失败。

本次实现：第一步读取最近公开交互，识别纠正/普通言行/需要澄清。纠正仅重演最近普通回合，从其开始快照恢复，原始事务快照和历史保留，成功保存后才标记旧回合被替代。手动修改后的世界拒绝自动回退；纠正不能生成 admin/narrator 权限。恢复后重新计算公开背景和新遇名单，不使用被撤回结果派生的背景。独立新遇人物使用程序生成 ID 和同一套三文档、验证器、助手配置接口。普通场景/记忆仅一次完整 replace，验证写入成功即结束，不再要求多余的 done；空参数仍不是成功。

验证：CSP 禁止动态代码生成环境下 324 项通过；TypeScript 与 EXE 构建通过。新增测试覆盖重演撤回错误记忆、原文不投递、恢复后新人物登记、事务失败不改原存档、连续纠正、手动变更冲突、admin 越权拒绝、明确角色对白、人物数量/字段校验、助手读写新人物和历史保留、已验证替换结束。浏览器通过受控 HTTP 连续两次输入、旧记录标记、纠正说明、刷新重载、新女孩详情、Trace 和 Raw Messages 检查，保留原页面风格。这些是确定性验证，不冒充真实模型语义验证。

真实模型：沿用已有 group_fast / deepseek/deepseek-v4.1-flash，独立存储。中间版本两轮虽然能提交，纠正时仍可能沿用旧背景或漏掉新人物（correction-live、correction-final-live），因此未作为最终回归通过证据。最终版本从同模型第一轮快照续跑第二条“不是这个，是另一个”（correction-replay-live/report.json）：31 次调用、130184ms、0 次工具错误，纠正原文未进入感知，重新登记的女孩获得招呼并独立回答“有什么事吗？”，提交版本 2。最终 Processor 源码哈希与该报告一致。旁白仍增写侧门、玩家沿路走来等未提供细节；没有把这次回归通过扩大为完整叙事保真或十轮验收通过。

## 2026-09-12：命令路由 → Designer → Narrator（routed-v2）

按用户确认的新结构替换 v1 多阶段流程：命令路由选择人物并给出指示；需要新人物时一次 Designer 创建卡片；一次 Designer 批量返回人物表达、动作、完毕状态；Narrator 整合消息与非空人物表现。没有人物时跳过 Designer，不再运行逐人物多轮认知、感知投递、文档工具、记忆回写或自动纠正重演。旧代码及 v1 阶段专用测试归档到 docs/archive，不再把废弃流程的集成测试当作新流程验收。

时间锚点存为 GameTurn.narration（anchor/requestText），请求中的历史 assistant 消息含程序附加的 `【时间点 i】`。正文显示、复制、人物详情与历史页不显示标记；开发者 Raw Messages 保留实际请求。固定 system、公共作者设定与历史构成稳定前缀，当前输入、路由指示、动态卡片与状态追加在末尾。各模型都收到用户原文，Designer/Narrator 还收到路由指示。代码测试验证前缀字节保持，不声称服务端缓存实际命中。

状态只记录在该回合 Designer 结果，与正文锚点关联；未选中人物不更新，双空表现不进旁白仍可更新内在状态。所有新卡片、状态、锚点、正文使用既有 CAS 与原子持久化一起提交。旧角色提示词/绑定保留，三个新角色独立继承旧文本角色的模型配置；AI 助手 agents/groups/textSaves 接口同步，运行状态与锚点拒绝作为可写配置。
