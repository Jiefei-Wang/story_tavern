输出结构补充（只规范格式，不增加玩家动作）：
顶层为 {"blocks":[...]}。每个 block 必须有字符串 id 和 kind；kind 只能是 normal、wait、time_skip、admin 中本次权限允许的值。
normal block 的玩家事件必须放在 events 数组内，不能把 action/speech 本身当 block。每个 event 必须有唯一 id、type；action 使用 actor="player"、op 及相应 target/item，speech 使用 actor="player"、content 和 target。
content 是 event 的直接字段；“action.content”指 action 类型事件上的 content，不是名为 action 的嵌套对象。物品用 item，目的地用 target；不添加 destination、objectId、object 或 action 子对象。使用请求给出的现有 ID，不复制示例 ID 作为新实体。

完整最小示例：原文若是“把杯子放到桌上”，且当前已有 cup 与 table，可输出：
{"blocks":[{"id":"b1","kind":"normal","events":[{"id":"e1","type":"action","actor":"player","op":"put_down","item":"cup","target":"table","content":"把杯子放到桌上","duration":1}]}]}

当前原文若明确“听老师讲下一步”，且 teacher 是在场对象，回应请求的格式示例是：
{"blocks":[{"id":"b1","kind":"normal","events":[{"id":"e1","type":"action","actor":"player","op":"listen_to","target":"teacher","content":"听老师讲下一步","duration":1,"responseRequest":{"target":"teacher","sourceText":"听老师讲下一步"}}]},{"id":"b2","kind":"wait","responseWindow":true}]}

示例只演示嵌套层级。实际事件数量、动词、ID、原文片段、时长及是否需要回应窗口均按当前输入决定，不给普通动作额外套用等待。明确等待时长使用 wait block 的 duration（秒）；time_skip 在 block 上填写 to；只有获得显式开头管理员授权才使用 admin 并在 block 上填写 command。输出前只核对 block 的 id/kind 与 event 的 id/type 是否齐全、事件是否在 events 内，不输出解释或自检记录。
