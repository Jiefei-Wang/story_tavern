# 第二轮：可见的简短核对摘要与编译格式说明

第一轮的精简三步提示没有达到接入门槛，正式代码和存储配置保持不变。本轮继续用原18个请求，每项3次，仅运行新candidate；对照为v1已保留的baseline和candidate，不声称是新的同期双臂实验。

两种改动按角色分开：

- input_compiler：补回完整的block/event格式样例及必需字段，解决v1候选提示删除格式说明后产生的扁平blocks问题。原用户输入和原输出Schema不变。
- 其他三个角色：在生成答案前输出1至3条简短、可核对的输入事实摘要，再输出answer。不要求冗长思维过程。实验输出为 `{evidenceSummary:[...], answer:原角色JSON}`，只有answer按原角色Schema使用；外层结构也校验。这与v1只要求内部核对不同，不能把效果全部归因于提示词变短。

模型、temperature、top_p、max_tokens和reasoning_effort仍逐请求匹配原记录。没有改上下文事实、补金标准或修改正式解析器。每次一次请求，不做格式重试；原始完整回复保留，方便核对摘要本身是否也理解错。

沿用v1的人工标准与接入门槛。疑虑方向样本保留原预期，但评审发现单次请求的字段含义存在歧义，单列disputed，不以强制涨跌作为成功证明。不移除它来美化通过率。
