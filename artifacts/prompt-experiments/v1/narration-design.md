# 旁白与审计提示词实验 v1

本实验只提供两个替换system字符串，不修改src、Agent配置、冻结预期或历史输出。目标是检验：将重复的长禁令改成“当前事实 → 事件与范围 → 全文一致”三步短核对，是否能减少方向颠倒、限定范围丢失和顺手补剧情，同时保留自然表达。

提示词文件为[narration-prompts.json](/E:/code/story_tavern/artifacts/prompt-experiments/v1/narration-prompts.json)，顶层恰含`narrator`、`narration_auditor`，值均为字符串。没有新增运行时字段，没有要求输出思维链；仅在内部做简短核对，仍返回原JSON结构。

## 依据与职责

阅读了[trajectory现代场景原始请求](/E:/code/story_tavern/artifacts/behavior-tests/trajectory-live/modern-legal-item.json)中第1轮两角色的resolvedMessages。实际用户数据已经包含结束实体、带outcome的有序事件、公开patch和起止时钟；不是缺少方向证据，而是source.op的动作词覆盖了已提交流向。旧旁白system为多条合同、事实策略和时间/允许来源提示，审计也叠加了长事实策略。本实验不再重复这些大段禁令。

[trajectory承诺场景](/E:/code/story_tavern/artifacts/behavior-tests/trajectory-live/promise-repair.json)第5轮显示另一种错误：SpeechPlan限定本次没有接到物品，生成的对白变成当前没有持有任何东西；这不是强迫角色诚实能解决的问题，而是表达扩大了原意的时间及量词范围。第一次审计只看见开头位置措辞，重写后未发现后面对白矛盾，所以新审计明确覆盖所有段落及重写后的全文。

[延迟回忆定向复核](/E:/code/story_tavern/artifacts/behavior-tests/targeted-reviews/delayed-recall.md)中的整理书架和手边记录，说明转场常把普通发言或抽象记忆扩成实体动作。实验要求查这些具体事实来源，但不会把纯修辞或“可以这样说”的风格差异当成错误。

生成器只负责忠实表现，保留角色原意，包括谎言、保留态度或推测。审计器独立比较资料与所有segments，输出局部证据和最小修正要求，不抢写故事。两者都按已提交状态和时序读取动作方向，而不是按短op词补足想象。若资料本身冲突，生成器只表达确定范围；审计器仍不能从隐藏世界猜解法。

## 重放约定

- 建议在实验runner中替换该角色真实请求的全部system策略消息为对应实验字符串，保留原user公开资料、模型、参数和输出schema。仅换首条而继续附加旧长policy会变成叠加实验，应另命名，不与本实验混报。
- 输入不包含人工gold、评语、失败标签或完整测试预期。审计原始失败输出时只给其原公开上下文与待审segments；审计新生成输出时使用相同公开上下文。
- 原协议结构校验照旧；结构成功与行为通过分开计数。审计必须能指出错误，也要保留合理表达，不能靠全部拒绝获得表面召回率。
- 留存原/新请求、原/新输出、模型参数、模型版本可得信息、提示词文件hash、阶段一结构结果和人工判定。成功重放不追溯修改原失败记录。
- 本文件的配对例子是离线评估建议，不嵌入system提示词，不将其判定标签发给模型；不要只用设计时见过的失败案例宣布泛化成功。

## 建议失败/通过配对 cases

每对共享公开上下文，只改待审表达；失败与通过都是人审期望，不是固定生成台词。可分别用来测旧输出审计、新旁白生成和新输出审计。

| 对照 | 公开上下文 | 应拦的变体 | 应放行的变体 |
| --- | --- | --- | --- |
| 单次接收 vs 当前持有 | B已经持有一份地图；本轮额外给予失败；speechPlan只说本次没有收到新物品 | 对白断言自己目前什么物品都没有 | 对白自然表达本次没有新增交付，保留已持有地图 |
| 移动方向 | 事件source.op名称含取用，但确定效果将现有工具从A移入箱子，结束位置为箱子 | 写A从箱中取走并拿在手中 | 写实际放入，或仅写工具已置于箱内；不靠op翻转 |
| 缺少动作来源 | 馆员本轮仅回答开放时间，没有整理、拾取或移动事件 | 先写馆员放下正在分类的资料再作答 | 直接自然回应；环境只来自已知资料 |
| 抽象经历 vs 实体记录 | 角色上下文有亲历记忆，公开实体没有记录本，事件没有书写或查阅 | 写低头核对手边账本 | 自然回顾亲历；也允许非实物比喻，不暗示实际账本 |
| 局部失败 vs 全局不可能 | 本次开锁失败，不提供任何永久能力结论 | 断言此人永远不可能打开任何锁 | 保留此次失败与已知原因，不扩大到全部能力 |
| 条件 vs 当前事实 | speechPlan讨论若预约批准才能入场，当前没有批准 | 写批准已经下达、人物已经进入 | 保留假设条件并留在当前状态 |
| 总窗口 vs 额外等待 | 6秒inclusive窗口中有4秒NPC发言 | 先完整沉默6秒，再用4秒回答 | 窗口内自然停顿并回答，不额外计整段时间 |
| 全文覆盖 | 第0段有转移方向错误，第3段另有数量范围扩张 | 只报第0段，或修正第0段后把仍错的第3段判通过 | 两个有证据的问题均能指出，后续全文重审 |
| 忠实谎言 vs 生成器改意 | 已接受speechPlan明确角色故意否认自己知道消息；公开叙述不能认证否认 | 强迫角色坦白，或旁白将否认认证为客观不知道 | 保留角色否认，prose不替其证明；不能单因不诚实拦截 |
| 修辞 vs 真实物品 | 只有已知灯光、说话与短暂等待 | 凭空新增一面实镜供人物擦拭 | 用不落地为实物的“话语像镜面一样冷”等修辞，或普通自然停顿 |

同时保留完整真实请求回放：方向颠倒、范围扩张、无来源整理和实体记录至少各一个；通过控制应含已正确落地的接收、克制感谢、拒绝请求、无新属性变化但有真实发言。小样本改善只能报告为局部实验结果，不能视为已修复所有故事。
