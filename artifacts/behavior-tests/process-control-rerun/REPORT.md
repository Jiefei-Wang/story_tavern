# 小火苗执行对照：契约修复与实际重跑

**实际点燃和资源后结算已得到验证。** 同一既有蜡烛 `lit:false→true`，真实 `cast_spell` 完成后，米拉的 `mana:0.6→0.35`。原 NPC 没有预先扣魔力，Resolver 也没有再手写人物属性。人工对属性部分判通过；旁白主要事实有来源，但发言与施法排列顺序仍有疑点，整体保留有争议。逐项证据见 [manual-review.json](manual-review.json)。

## 首次失败的实际原因

[第一次记录](../process-control-live/low-magic-execution-control.json) 保持原样：Resolver 同时输出 `candle.lit=true` 和 `mira.attributes.mana=0.5`，违反人物提议选择协议，被 CharacterEffects 拒绝，整轮回滚。这是程序拦截了非法裁决，不是模型安全拒绝，不能豁免成剧情成功。

当时实际发送的运行时人物契约仍包含“采纳某项更新时使用其中该字段的完整最终值”“数值 delta 转成最终值 Patch”以及 text append 手写连接说明；同一请求后面的政策又禁止直接写人物属性。世界裁决也没有清楚获知已接受物理过程还会进入独立的完成后状态结算。世界规则要求施法有代价时，模型因此试图在本阶段补扣 mana。

## 最小通用修复

- `AgentContract.ts` 复用统一的 `CHARACTER_EFFECT_POLICY`，删除旧的 delta/append 手写人物 Patch 指令，继续保留用户自定义消息及运行时字段协议。
- `CharacterEffects.ts` 的政策明确：Resolver 提交物品、环境和位置等实际结果；既有人物提议只按下标选择；进食、休息、施法、治疗、运动和使用能力等身体或资源效果由动作完成后的独立阶段结算。不能因为缺少预先效果而补 Patch、造候选或拒绝可行动作。
- 内置 Resolver 的说明和示例同步该职责；AI 助手文档解释配置可编辑与提交边界。没有新增角色、放宽提交门禁、增加业务错误重试或静默删改非法 Patch。

新增确定性测试覆盖：旧契约替换而自定义消息保留；施法先点亮物体、后扣资源；Resolver 仍试图直写资源时，即使物体 Patch 合法也必须整轮回滚。相关 28 项 CSP 测试和 TypeScript 检查通过。

## 重跑配置与人工事实检查

新快照为 `unit-test-config.process-control-v2.json`，所有既有组、绑定和后端配置与旧 fixed 完全一致，仍使用 unit test 组及 `deepseek/deepseek-v4.1-flash`。角色定义同步当前版本，人物因果审计为 v1.2；旧配置未覆盖。三角色快照是 `process-control-roles-v2.json`。

Resolver 本次仅提交现有蜡烛的 `lit=true`，接受施法事件后，完成过程阶段实际看到点燃状态以及仍为 0.6 的 mana，再以 `turn_1_b1_event_3` 为唯一施法来源提出 -0.25。没有前后两次扣除，没有新增蜡烛或强力法术。原预期未规定具体扣值，只要求下降且不耗尽；0.35 满足该条件，不据个人偏好改成固定 -0.1。等待事件真实为三十秒，整轮另含玩家话语五秒，因此时钟共推进三十五秒。
