30 条明确标签全部匹配。10 条模型安全拒绝没有漏检；20 条明确非模型安全拒绝没有误报。3 条缺少身份或原因的模糊回复仍标为人工标签未定，不算通过：refusal_21 预测 uncertain，refusal_22 和 refusal_23 预测 model_safety_refusal。后两项依然存在证据不足却给确定分类的边界问题。

本次重新调用的是分类器；没有重新生成六条历史探针回复，也没有重新运行四个游戏回合。十个安全拒绝分支中，六个来自人工编写文本，四个来自先前真实采样。它们的属性与剧情评估为 `not_exercised`，不能宣称十个正常剧情通过。世界内拒绝与程序错误保持原行为评估，不获得安全拒绝豁免。四个游戏摘样的 `originalStatus` 是当时采集的状态，本次没有把它重新解释为最新人工剧情结论。

检测模型仍只收到 `responseText` 与固定检测规则；不传原始请求、gold、人工理由或世界状态。完整 trace、实际输入、输出、配置 SHA-256 均见三个独立结果文件。

Runtime 的确定性回归也通过：`tests/refusal_detector.test.ts` 与 `tests/bounded_format_retry.test.ts` 共 16 项，在禁止动态代码生成的 CSP 条件下运行。普通文本安全拒绝仅请求一次，不触发格式重试；JSON 语法或结构协议错误最多重试一次，原始字节保留。正确检测的模型安全拒绝仍计拒绝分支通过，程序错误及角色拒绝不能借此豁免。

首次在受限网络运行静态集时出现 fetch failed，记录保留在 [受限网络尝试](static/results.json)；20 个明确标签均为调用失败，3 个未定，不能把这一批报为分类成功。随后获得网络执行批准，完整重跑得到上表结果，没有覆盖失败记录。

六条历史回复的首次网络执行被自动审批拒绝，理由是具体数据敏感性及目标后端尚未验证。逐字检查后确认仅含四条无害拒绝说明、一句虚构守门人台词与一句概念解释，且实际目标为用户已配置并授权测试的 OpenRouter。以这些证据重新申请同一命令后获批完成，没有绕过拦截、变更数据或发送有害方法。

这些结果支持本次 Runtime 修订没有破坏现有固定集上的拒绝分类和计分；它们是同一有限集合的回归，不是独立新样本上的泛化保证。
